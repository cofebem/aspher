# ASPHER: accuracy and efficiency review

Review date: 8 September 2026. Source revision: `002b20d`.

The strongest next step is to make convergence an independently checkable
statement, then exploit the existing active-set H² architecture more fully.
The implementation already includes most of the obvious accelerations: exact
cell integration, translation caches, tensor leaf interpolation, compressed
candidate vectors, spectral preconditioning, nested initialization, reusable
buffers and float arithmetic with double iteration reductions. Recommending
these again would miss the actual remaining opportunities.

I read `CLAUDE.md`, the normal and tangential kernels/operators/solvers,
the nested and active-set drivers, bindings, tests, relevant theory notes,
and earlier experiments. The review's main scope is normal rough contact;
the friction findings are an additional audit of that newer subsystem.
Production source and configuration files were not changed. Two standalone
experiments accompany this report:

- [`review_20260908.py`](../experiments/review_20260908.py): correctness,
  numerical stability, approximation ranks, and displacement reuse.
- [`review_20260908.cpp`](../experiments/review_20260908.cpp): construction,
  translation microbenchmarks, and preconditioner scaling.

A fresh build succeeded. All 12 CTest groups and all 9 selected Python
integration tests passed (`test_h2.py`, `test_nested.py`,
`test_friction_py.py`). The review probes were then repeated against the
rebuilt library. Thus the counterexamples coexist with a passing existing
suite; they identify missing coverage. Raw probe output is preserved in
[`review_20260908_results.jsonl`](../experiments/review_20260908_results.jsonl)
and [`review_20260908_cpp_results.txt`](../experiments/review_20260908_cpp_results.txt).

Measurements use four OpenMP threads; Python's BLAS uses one thread. Small
benchmarks establish mechanisms, not workstation-wide or large-grid speedups.
In particular, no 16384² solve was run. Memory savings at that size below
are exact storage calculations, not new peak-RSS measurements.

## 2. Convergence currently does not certify a contact solution

In `src/contact_solver.cpp:78`, the error is

\[
 e_{PK}=\frac{\sum_i p_i|g_i|}{P\,g_{scale}},\qquad
 P=N\bar p,\quad g=Sp+g_0-\alpha\mathbf1.
\]

It tests pressure-weighted stationarity, but says nothing about negative gap
where pressure is zero. This is explicitly recognized in `CLAUDE.md` and in
the active fallback's pressure-seeding workaround; it is still present in
the general solver and the restricted solver.

The shortest counterexample is any one-point positive warm start. The
computed approach makes that point's gap exactly zero, so the error is zero
regardless of what happens everywhere else. The experiment uses an ordinary
parabolic gap, Ns=8, p̄=0.01, with all initial load at a corner. It returns:

| Quantity | Value |
|---|---:|
| `converged` | true |
| Iterations | 0 |
| Reported error | 0 |
| Maximum penetration | 0.46026847 |
| Relative pressure error against the cold solution | 2.23606798 |

The independent simplex-projected gradient prototype repairs this warm
start in 162 iterations, reaches a certificate below 10⁻¹², and agrees with
the cold solution to absolute pressure L2 error 3.20×10⁻¹¹. Its purpose is
an independent correctness check, not a proposed replacement at this speed.

### A cheap certificate with a proof

Let S be symmetric positive definite, let p be feasible, and put

\[
 f(p)=\tfrac12p^TSp+g_0^Tp,\quad v=Sp+g_0,\qquad
 \mathcal G(p)=p^Tv-P\min_i v_i
             =\sum_i p_i\big(v_i-\min_jv_j\big).
\]

The second expression is preferable numerically: nonnegative summands avoid
subtracting two large nearly equal totals. It is the Frank–Wolfe gap over
the load simplex, used here as a certificate rather than as an iteration.

Proof: convexity gives
\(f(p)-f(p_*)\le v^T(p-p_*)\).
Since \(p_*\ge0\) and \(\mathbf1^Tp_*=P\),
\(v^Tp_*\ge P\min_i v_i\). Therefore

\[
 0\le f(p)-f(p_*)\le\mathcal G(p).
\]

Furthermore, \(\mathcal G=0\) iff every positive-pressure point attains
the minimum gradient. Taking \(\alpha=\min_i v_i\) then gives all three
contact conditions: p≥0, g≥0, and pᵢgᵢ=0. For a load-feasible iterate and
\(S\succeq mI\), optimality at p* also gives

\[
 \tfrac12\|p-p_*\|_S^2\le f(p)-f(p_*)\le\mathcal G,
 \qquad \|p-p_*\|_2\le\sqrt{2\mathcal G/m}.
\]

The same argument works with coercivity restricted to the zero-sum feasible
tangent space. These are discrete-QP bounds; they do not bound continuum
discretization error. Floating-point implementations need an allowance for
roundoff in the certificate itself.

Implementation recommendation: retain the familiar PK diagnostic, but also
return load error, pressure infeasibility, maximum penetration, and this
certificate. Normalize G by a documented P×displacement scale. All require
only reductions after an already required matvec. Near termination, perform
the check with a freshly evaluated displacement. At max_iter the current
code recomputes fields but does not recompute `res.error`; repair that too.

Simply refusing the current early exit is insufficient: with a singleton
support, the restricted direction is zero. A violated outside constraint
must enter via a feasible projected-gradient step or an explicit active-set
expansion before attempting restricted CG again.

### Stagnation must be a separate termination status

`src/contact_solver.cpp:92` and its restricted counterpart set
`converged=true` after 200 insufficient improvements. The tangential solver
does this too. That describes an algorithm stopping, not a tolerance being
met. It can happen in double precision: the preconditioner-scaling experiment
below produces exactly this failure.

Use statuses such as `converged`, `stagnated`, `max_iterations`,
`nonpositive_curvature`, and `nonfinite`. Preserve the best certified iterate.
Record requested and effective tolerances separately when float clamps the
requested tolerance. Transactional callers must commit only a certified
result, not a stagnation result.

### Candidate expansion has the same hole

The stream in `src/nested_solve.cpp:211` examines only points outside C.
Expansion at line 244 copies the old pressure and leaves newly added points
at zero. If the old restricted solution satisfies the PK metric, the next
restricted solve can immediately exit; the newly added penetrating points
are now *inside* C and are excluded from the next outside-only scan.

This is a direct control-flow failure mode, not a claim that all benchmark
surfaces trigger it. The full fallback seeds violations, but this expansion
path does not. Check the restricted KKT conditions on all candidate points,
activate newly violated points, and combine the restricted certificate with
the global streamed minimum gradient. An empty outside violation list alone
must not be called a global certificate.

## 3. The preconditioned overlap step is not scale invariant

The contact direction uses z=M⁻¹g, but the overlap correction at
`src/contact_solver.cpp:153` uses the raw g and the same step τ.

Replace M⁻¹ by cM⁻¹. On an unchanged support the CG direction scales by c,
the line-search numerator by c, and its denominator by c². Thus τ scales by
1/c and the ordinary pressure update τt is unchanged. The overlap update
τg instead scales by 1/c. The assertion that the preconditioner's absolute
scale cancels is therefore true only for the fixed-support part.

The C++ experiment holds the gap/operator/load/tolerance fixed at Ns=64:

| Multiplier on the Fourier preconditioner | Iterations | `converged` | PK error | Relative pressure difference from c=1 |
|---:|---:|---|---:|---:|
| 1 | 22 | true | 2.72×10⁻¹¹ | 0 |
| 10⁻³ | 208 | true | 1.96×10⁻¹ | 2.13 |
| 10³ | 22 | true | 2.72×10⁻¹¹ | 2.46×10⁻¹² |

The failure combines scale-sensitive overlap with false stagnation success.
The experiment does not imply that the default scaling fails on the usual
surfaces; it shows that tuning or replacing the preconditioner is currently
less safe than the linear-CG argument suggests.

There is another mathematical mismatch: `delta` is reset when overlap occurs,
but not for every removal from the contact set. Restricting an old zero-sum
direction to a smaller support need not preserve zero sum. The nominal exact
line search is then followed by a pressure renormalization that changes its
path. This is a heuristic projected-CG iteration, not unconstrained PCG with
an exact feasible line search on every step.

A principled alternative is a two-phase method: simplex projection for
identification, followed by PCG on the current support and its zero-sum
subspace, with a feasible step length and restart on support changes. For
support C, use
\(Q_C=I-\mathbf1\mathbf1^T/|C|\) and a symmetric projected preconditioner
\(Q_CM_C^{-1}Q_C\). Projection onto the load simplex is
\(p_i=\max(y_i-\theta,0)\), with θ determined by the load. Sorting gives a
simple reference implementation; selection or safeguarded scalar threshold
search avoids a full sort in production.

The equality constraint is not an unsolved obstacle to this approach:
[di Serafino, Toraldo, Viola and Barlow](https://arxiv.org/abs/1705.01797)
study precisely quadratic problems with one linear constraint and bounds,
using identification and reduced minimization phases. This is a better
starting point than directly transferring a bound-only GPCG implementation.
Any replacement still needs ASPHER-specific benchmarking; no speedup is
claimed here.

## 4. Float precision: remove physically irrelevant offsets first

For a fixed load,
\(f_{g_0+c\mathbf1}(p)=f_{g_0}(p)+cP\), so adding a constant to g₀
cannot change p*. It only adds c to the approach.

The current nested float path casts the uncentered gap before solving.
The Ns=128 rough-contact experiment shows:

| Gap offset | Center before float conversion? | Finest iterations | Pressure relative error against double FFT |
|---:|---|---:|---:|
| 0 | — | 7 | 4.84×10⁻⁵ |
| 10³ | no | 211 | 1.26×10⁻² |
| 10³ | yes | 7 | 4.84×10⁻⁵ |
| 10⁶ | no | 1 | 1.08 |
| 10⁶ | yes | 7 | 4.84×10⁻⁵ |

All these float calls report convergence. With offset 10³ the reported
error is 1.51×10⁻⁴, above the effective 2×10⁻⁶ tolerance. With offset 10⁶,
the error is zero because rounding has removed essential variations.

Center in double before casting and before forming u+g₀ in float; carry the
offset separately and restore it to the approach. Nondimensionalization is
the next step: choose displacement scale g_ref and pressure scale
E* g_ref/L, giving dimensionless operator (E*/L)S. Scale tolerances from
physical variation/compliance, not an arbitrary additive datum.

Uniform multiplicative rescaling of gap and pressure by 10³ and 10⁶ worked
well in this experiment; the demonstrated failure is specifically loss of
small variations beside a large offset. Centering after information has
already been lost in a caller's float array cannot recover it.

For accurate final pressures, use float to identify contact, then polish the
restricted problem in double with a fixed accurate operator and a full-grid
certificate. This offers a clearer accuracy contract than returning float
results as double arrays. Warm-start `p.sum()` and the full solver's final
objective/mean also still reduce in Real; use double there for consistent
large-grid diagnostics.

## 5. Separate solver error, H² error, and discretization error

The FFT backend is an excellent *discrete* reference: it applies the same
Love coefficients as dense assembly. Agreement to roundoff between those
two paths checks convolution correctness; it does not independently check
the kernel formula or continuum accuracy.

At Ns=128 on a fixed band-limited rough surface, all three H² runs use
tol=10⁻¹⁰ and finish in 22 iterations:

| q | Pressure relative L2 error vs FFT | Relative displacement error on returned p | Maximum penetration evaluated with FFT |
|---:|---:|---:|---:|
| 4 | 5.07×10⁻⁵ | 1.23×10⁻⁴ | 1.24×10⁻⁶ |
| 6 | 9.46×10⁻⁷ | 2.08×10⁻⁶ | 1.24×10⁻⁸ |
| 8 | 2.39×10⁻⁸ | 4.52×10⁻⁸ | 6.56×10⁻¹⁰ |

The contact-area difference is exactly zero in all three cases. Area alone
is consequently a weak operator-accuracy test. The FFT reference has maximum
penetration 2.19×10⁻¹¹. A tiny residual for the approximate operator cannot
certify the same residual for the exact discrete operator.

Useful tests include contact pressures, isolated source patches, signed
zero-mean directions, high-frequency modes, and random vectors. Compare
pressure, displacement, compliance, gradient certificate, load, and area.
Small-grid eigenvalue/reciprocity tests should supplement random matvec
tests. The measured H² bilinear symmetry defect here is approximately
6×10⁻¹⁴–1.4×10⁻¹³ under the experiment's normalization; this is a numerical
observation, not a proof of positive definiteness at all q/grid sizes.

### A certificate that explicitly includes operator error

Suppose \(\tilde v=\tilde S p+g_0\) and a justified bound gives
\(\|Sp-\tilde S p\|_\infty\le\epsilon_u\). For feasible nonnegative p,

\[
 \mathcal G_S(p)\le\mathcal G_{\tilde S}(p)+2P\epsilon_u.
\]

Proof: the weighted-gradient term changes by at most Pεᵤ, and its minimum
changes by at most εᵤ. This makes the distinction between iterative and
operator tolerance explicit. Comparing q and q+2 estimates εᵤ empirically;
it is not itself a rigorous bound. An FFT check is useful where affordable;
otherwise use a better-resolved FMM plus clearly stated uncertainty or
validated interpolation bounds.

Use staged accuracy: low q/float for identification, then restart at higher
q/double for final correction. Keeping the operator fixed within each CG
phase makes this substantially easier to reason about than changing q on
every Krylov application. A blockwise SVD tolerance also needs propagation
through interpolation/transfer norms; it is not automatically a global
pressure-error tolerance.

Symmetric compression matters. Construct reverse couplings as transposes
and use compatible source/target bases. Symmetry alone does not imply SPD:
if \(\tilde S=S+E\) is symmetric and
\(\|E\|_2<\lambda_{min}(S)\), SPD follows, but a local truncation test does
not establish this global inequality. Prefer energy-relative error bounds
or final certification with the reference operator.

## 6. Stable kernel evaluation is needed at large separation

`love_uz` directly subtracts logarithmic corner expressions. Far away, the
answer is of order h²/r while the constituent terms are much larger. Signed
arguments also cause cancellation inside quantities such as x+sqrt(x²+y²).
The normal H² far callback passes signed offsets directly; unlike the
near-table path, it does not first fold them to positive coordinates.

The Python experiment mirrors the production expression and compares it
with the same integral evaluated using 80-digit arithmetic. For h=1:

| (x/h,y/h) | Relative error of current expression | Relative error of 4×4 Gauss integration |
|---|---:|---:|
| (32,0) | 1.07×10⁻¹³ | 4.4×10⁻¹⁶ |
| (16384,0) | 4.64×10⁻¹⁰ | 4.4×10⁻¹⁶ |
| (16384,16384) | 1.86×10⁻⁷ | 3.3×10⁻¹⁶ |
| (−16384,−16384) | 1.49×10⁻⁷ | 3.3×10⁻¹⁶ |
| (−10⁶,0) | approximately 1 | 2.2×10⁻¹⁶ |

The million-cell offset is a stress test beyond current solve sizes. The
16384-cell scale is relevant to intended large grids, but these are sampled
entry errors, not measured full-solve errors at Ns=16384. At a cell corner
(x=y=h/2), the expression returns NaN although the integral is finite.
Normal integer-offset tables avoid that corner; the public continuous
kernel still needs its removable singularities handled.

Use analytic near/self integration with explicit edge limits, parity folding
for the even normal kernel, stable log/asinh forms, and a far branch using
positive-weight quadrature or a controlled moment expansion. For a square,
Taylor averaging gives

\[
 \int_{cell}\frac{dA'}{|r-r'|}
 =\frac{h^2}{r}\left[1+\frac{h^2}{24r^2}
             +O\big((h/r)^4\big)\right].
\]

The coefficient follows from ⟨x'²⟩=⟨y'²⟩=h²/12 and the in-plane identity
Δ(1/r)=1/r³. Higher orders have angular dependence. This also explains why
replacing the far Love kernel by a point kernel everywhere is not exact.
The 4×4 quadrature prototype avoids subtracting nearly equal large terms;
its sampled results are not a uniform error proof or a kernel-speed
benchmark. Choose and validate the switch radius against quadrature bounds
and high-precision samples across angle and element aspect ratio.

Cerruti's diagonal logarithms and cross-component differences of radii
deserve the same audit. Preserve the required odd/even component parities.
Do not reuse one level's integrated-kernel couplings at all levels by a
simple homogeneous rescaling: h is fixed while box size changes, so the
cell correction changes with level.

## 7. Remove the full Love table from the H² build path

Both the nested driver and `PyContactSolver` construct `BoussinesqKernel`,
allocating and filling Ns² doubles, even for H². After H² construction the
matvec uses its own caches. For leaf side ℓ and near radius r_n, the required
absolute near offsets satisfy

\[
 |d_x|,|d_y|\le(r_n+1)\ell-1.
\]

Thus the compact table needs only
min(Ns,(r_n+1)ℓ)² entries. At ℓ=8 and r_n=1, it is 256 doubles, or 2 KiB.
The existing generic H² constructor already makes this possible without a
new numerical algorithm.

The C++ prototype preserves exactly the original near/far arithmetic and
finds bit-for-bit identical output on a random 1024² vector. One run gives
39.6 ms for the full table plus 26.6 ms for H² construction, compared with
24.8 ms for compact-table construction plus H². A previous run gives the
same equivalence and a similar ratio. These are build timings, not matvec
or full-contact-solve speedups.

The storage saving is 8N bytes minus the small cache: 2 GiB at Ns=16384 and
8 GiB at Ns=32768. Implement it in both the nested and explicit H² paths;
retain appropriate coefficient generation for FFT/dense/H-matrix backends.
The same constructor separation can avoid full Cerruti tables for H².

## 8. Reuse displacement when the pressure update is linear

Currently each PK iteration applies S to p and to t. If no clamp or overlap
changes the update, and load normalization is f, then

\[
 p_{k+1}=f(p_k-\tau t_k)
 \quad\Longrightarrow\quad
 u_{k+1}=f(u_k-\tau S t_k).
\]

This is exact by linearity and saves the next S p. Refresh after any nonlinear
projection, periodically to control accumulated rounding, and always before
final certification. When projection produces a sparse correction d, the
more general identity is
\(u_{k+1}=f(u_k-\tau St_k+Sd)\); the existing masked H² path might evaluate
Sd cheaply, but that extension was not benchmarked here.

The separate NumPy PK experiment, using ASPHER's FFT matvec and a Fourier
preconditioner, compares the same algorithm with and without this reuse:
22 iterations in both; 45 → 37 operator calls; pressure relative difference
9.86×10⁻¹⁶. Refresh period is 20 iterations. Small Python wall times were
approximately equal (~30 ms), so this is evidence of saved operator work,
not a demonstrated production speedup. A C++ integration should measure
full solves at larger grids and dilute/dense contact separately.

## 9. Optimize FMM translations selectively

M2M/L2L store dense q²×q² transfers even though each is a Kronecker product.
Applying \(R=B\otimes A\) as
\(\operatorname{vec}(AXB^T)\) reduces work from order q⁴ to order q³.
The identity is exact, with floating-point reassociation as the only
difference. However, the compiled microbenchmark gives:

| q | Dense-time / tensor-time | Relative output difference |
|---:|---:|---:|
| 4 | 0.63 | 1.85×10⁻¹⁶ |
| 6 | 0.60 | 2.48×10⁻¹⁶ |
| 8 | 1.19 | 3.11×10⁻¹⁶ |

The dense path wins for q=4/6 with these Eigen kernels. Keep it unless
specialization/batching changes the measurements; consider tensor transfers
for higher orders. This test measures individual transfers, not a full FMM.

M2L is a better compression candidate at higher q. Across the 40 possible
2-D relative offsets for near radius 1, at leaf side 8:

| q | Relative singular-value cutoff | Median rank | Maximum rank | Mean factored/dense multiply count ratio |
|---:|---:|---:|---:|---:|
| 4 | 10⁻⁶ | 8.5 | 12 | 1.175 |
| 6 | 10⁻⁶ | 8.5 | 14 | 0.533 |
| 6 | 10⁻⁸ | 13 | 20 | 0.800 |
| 8 | 10⁻⁶ | 8.5 | 14 | 0.300 |
| 8 | 10⁻⁸ | 13 | 22 | 0.463 |

For an r×r matrix and retained rank k the ratio is 2k/r. Store a compressed
pair only when it beats the dense representation. These are rank/FLOP
measurements for one level, not measured full-matvec speedups. With q=6,
10⁻⁶ block compression is comparable to the interpolation error and may be
too aggressive for a stringent final certificate.

Investigate shared SVD bases, grouping interactions by level/offset for
GEMM, and square-grid symmetry permutations. Opposite offsets can share a
transpose; normal-kernel D4 symmetries reduce unique geometry further.
Retain different scheduling for dense and sparse target occupancy: batching
that accelerates a full grid may waste work on sparse contact.
These methods are supported by
[Fong and Darve](https://mc.stanford.edu/cgi-bin/images/f/fa/Darve_bbfmm_2009.pdf)
and [Messner et al.](https://arxiv.org/abs/1210.7292), but their reported
speedups should not be transplanted to ASPHER without measurement.

Near-field cost is roughly proportional to Nℓ² for a fixed neighborhood,
whereas far work scales roughly as Nq⁴/ℓ² before compression. Consequently
ℓ must be tuned jointly with q, precision and occupied-leaf fraction.
For larger leaves, batch dense near stencils or investigate exact local
convolutions with correct block padding; do not assume ℓ=16 is faster merely
because it saves tree memory. Add timings for P2M, M2M, M2L, L2L and near
evaluation before choosing the next kernel to optimize.

## 10. Sparse contact still carries substantial global overhead

Compressed vectors are an important improvement, but masked passes still
loop over all leaves/boxes and test occupancy. M/L buffers retain columns
for the complete tree, interaction lists are global, and indexed Fourier
preconditioning clears and transforms an Ns² grid. Total solve complexity
and memory are not O(N_candidate), even when CG state is compressed.

Build per-level occupied source/target lists and compact interaction walks
when C changes, amortizing the build over the restricted iterations. In
particular, `slot_leaf` already supplies occupied leaf indices for P2M/L2P.
Keep full-target streaming verification as a separate traversal. Eventually
compact occupied M/L storage as well; implement carefully because source
and target ancestry requirements differ between solve and verification.

Measure sparse preconditioner cost separately. The full FFT may dominate
after sparse matvec acceleration. Candidate alternatives include overlapping
local exact contact blocks plus a global coarse correction, projected onto
the zero-sum subspace. A symmetric additive construction
\(Q(\sum_jR_j^TB_j^{-1}R_j+ZB_0^{-1}Z^T)Q\) is positive on the tangent
space when its SPD components cover that space. It can be used by PCG;
mesh-independent conditioning is a further property that must be established
or measured, not assumed from positivity.

The earlier `block_gs_results.md` demonstrates poor frozen-far-field Jacobi
iterations. It does not rule out a Krylov preconditioner with a coarse space.
Do not confuse \((S_{CC})^{-1}\) with \((S^{-1})_{CC}\); their difference
contains the eliminated complement's Schur contribution. This helps explain
why restriction alone does not remove conditioning problems.

The certificate also yields a conservative screening theorem. Let
η=√(2 S_ii G), which is common to all points on this uniform normal grid.
The energy bound gives |vᵢ−v*ᵢ|≤η, and
|min v−min v*|≤η. Therefore

\[
 v_i-\min v>2\eta\quad\Longrightarrow\quad p_{*,i}=0.
\]

For nonconstant diagonals use ηᵢ+maxⱼηⱼ. This is safe screening for an
exact SPD operator and a valid feasible certificate; it becomes useful as
G decreases. It is likely conservative early on. Include operator-error
bounds before applying it to approximate H² fields. This supplies a
mathematical direction for replacing fixed `active_delta` heuristics without
pretending that q-versus-q+2 differences are rigorous bounds.

## 11. Memory accounting and the H-matrix fallback

`H2Info::bytes_total` counts double couplings, near stencils and estimated
M/L storage, but omits boxes, interaction records, CSR offsets, leaf lists,
transfer/leaf matrices, float cache copies, and the separately owned kernel
table. At Ns=1024, q=6, ℓ=8, the prototype reports 15,365,952 bytes while
boxes/interactions/CSR offsets alone add at least 7,072,776 bytes. The Love
table adds another 8,388,608 bytes outside the operator.

Expose actual allocated bytes by category and anticipated solve peak
separately. Current H² and FFT info methods do not count the same things.
Track full Python-process peak and C++ solve peak separately too.

The classical H-matrix ACA implementations allocate U(m,kmax) and
V(kmax,n), with kmax=min(m,n), before discovering a usually small rank
(`src/hmatrix.cpp:129` and 272). A large admissible block can therefore
reserve dense-sized temporary storage. Incrementally grow bounded column
capacity; on reaching a rank budget, subdivide or use a documented fallback
rather than silently truncating a requested accuracy.

Independently approximated transpose blocks also need a symmetry contract.
Sharing one triangular representation can reduce storage; row-owned
parallel work or controlled reductions are needed to avoid races. The
current H-matrix matvec allocates one full N-vector per OpenMP worker and
serializes their accumulation in a critical section. Scheduling disjoint
target rows can remove that O(N×threads) scratch and serial reduction.
Prioritize this only if the H-matrix backend remains important; H² is the
natural backend for the current uniform sparse-contact workload.

## 12. Accuracy of the physical/discrete model

Love integration is exact for a constant pressure source cell observed at
the target center. It does not eliminate error from representing pressure
by constant cells or resolving a moving contact boundary with binary cells.
A source-and-target integrated Galerkin discretization would instead use

\[
 S^{G}_{ij}=h^{-2}\int_{A_i}\int_{A_j}G(x-y)\,dy\,dx.
\]

It remains translation invariant on uniform cells and thus compatible with
FFT/H². Its energy positivity follows from the positive Fourier multiplier
of the half-space kernel applied to the piecewise-constant pressure field.
It changes what gap and displacement DOFs mean, and is not automatically a
pointwise-contact accuracy improvement; compare like observables and use
consistent cell-averaged geometry. Treat this as a research branch, not a
drop-in kernel patch.

The existing area-correction study already implements your perimeter-based
correction. Expose raw area, perimeter and corrected area consistently in
the API, with applicability information. The correction is supported by
[Yastrebov, Anciaux and Molinari](https://arxiv.org/abs/1701.02727);
it is a statistical/geometrical estimator, not a universal per-realization
error bound or a correction to the pressure field. Anisotropy, edge contact,
percolation and unresolved tiny patches need separate validation.

For convergence studies, hold the physical realization and spectral cutoff
fixed while refining h. Adding shorter wavelengths with each grid changes
the physical problem. Also distinguish periodic roughness generation from
periodic elasticity: the current zero-padded FFT/H² operator describes the
isolated loaded region on a half-space. A periodic cell needs its own
periodized operator and explicit mean-mode convention.

The current nested cascade restricts gap by averaging, prolongs pressure by
injection, and rediscretizes the operator at each level. This is a useful
initialization scheme, not a proven Galerkin multigrid cycle. A future
coarse-correction solver must account for the constraint and the mismatch
between its rediscretized S_c and R S_f P; simply iterating the cascade does
not establish multigrid convergence.

## 13. Additional friction findings

The tests and existing theory correctly specify uncoupled normal/tangential
elasticity (similar materials, Dundurs β=0). A rigid body on a compressible
elastic body is not generally in that uncoupled class. Keep this scope
explicit in examples; extension to dissimilar materials requires the
normal–tangential cross kernels and coupled equilibrium.

Three implementation issues deserve attention now:

1. **Changing normal load can invalidate stored shear.** After a converged
   Ns=32 Coulomb step at p̄=0.01 and q̄ₓ=0.001, a normal-only step to
   p̄=0.0001 returns success but retains shear at 76 open points. Maximum
   excess |q|−μp is 0.02362. The code updates p but runs no tangential
   relaxation when neither q_bar nor delta_t is supplied. Define the held
   tangential boundary condition during normal changes, then solve the
   corresponding incremental problem before committing. Clipping alone
   enforces the cone but generally does not enforce equilibrium/history.
2. **Zero load is conflated with “no normal update.”** `p_bar=0` is skipped,
   so the same probe retains mean pressure 0.0001 after requesting zero.
   Use a missing-value/sentinel state for “unchanged” distinct from physical
   zero, and define full separation with consistent shear/history handling.
3. **A dimensional bug contradicts its adjacent comment.** At
   `src/friction_driver.cpp:103`, g_floor adds |q_bar|, a pressure, to |u_t|,
   a displacement, under force control. Convert through a compliance scale
   or use a purely displacement-valued floor. Validate under changes of
   E*, L and units, not only E*=L=1.

The tangential solver's stall-success and terminal force correction also
need fresh KKT checks. The latter changes q but explicitly leaves
`res.error` describing the earlier iterate (`src/friction_solve.cpp:520`).
Exact total force is insufficient to establish local stick/slip equilibrium.

A robust residual for the fixed-threshold convex subproblem is

\[
 R_\rho(q)=q-\Pi_{\{|q_i|\le s_i\}}
 [q-\rho(Cq+u_{hist}-E\delta_t)].
\]

For any ρ>0 it vanishes exactly at the variational inequality solution.
Inside a disk the projection derivative is I; outside it is
\(s_i/|z_i|\,[I-\hat z_i\hat z_i^T]\). These local 2×2 derivatives and
the existing C matvec support a semismooth Newton formulation with
globalization. Its full Jacobian need not be symmetric; use an appropriate
linear solver or derive a symmetric reduced system, rather than assuming
CG applies. This is a proposed way past the observed rotating-slip floor,
not an implemented performance result. Treat velocity-dependent thresholds
as an additional nonlinear problem and check their final fixed-point
residual using the final slip field.

For efficiency, a vector H² application can share the tree and propagate
two-component multipoles/locals together. The current tangential H² wrapper
stores three scalar operators and performs four scalar applications; normal
and tangential geometry/transfer machinery can be shared. The production
friction driver currently uses FFT operators, so merely optimizing the H²
wrapper will not change that driver's performance without backend plumbing.

## 14. Engineering safeguards and a practical implementation sequence

Additional source-level findings:

- Validate Ns, coarsest, q, leaf_side, radii, E*, L, tolerances and finite
  arrays before allocation/iteration. In particular coarsest=0 makes the
  nested level-generation loop non-progressing. Guard integer products:
  Ns=32768 fits signed N, but 2N and FFT padded-grid products can exceed
  signed int; use checked size/index types before extending sizes.
- Make H² build semantics explicit. `build()` appends interaction/coupling/
  leaf arrays without clearing them; repeated build is not a clean rebuild,
  and existing float caches become stale. Either reject repeat calls or
  reset every dependent cache and statistic. Add basic size/build guards to
  public H² applies, as the FFT path already has.
- The explicit Python solver's by-value wrappers still allocate/copy arrays,
  and each `result.pressure` property access copies a full grid. Provide
  safe NumPy views with correct ownership or an explicit copy/view API,
  and route repeated solves through the into-style functions.
- GIL release permits simultaneous Python calls on the same mutable-scratch
  operator. Document and enforce per-instance serialization or separate
  immutable operator data from workspaces. In FFTW builds, planner creation,
  destruction and thread-count settings also need appropriate serialization;
  `call_once` around thread initialization is not a planner lock.
  See [FFTW's thread-safety contract](https://www.fftw.org/fftw3_doc/Thread-safety.html).
- The nested solver changes process-wide malloc policy with mallopt despite
  the steady-state allocation improvements. Make this an application-level
  opt-in, and measure it, rather than silently changing host-process policy.
- Keep source mathematical documentation aligned with the actual restart,
  stopping and model assumptions. Numerical bitwise identity to a previous
  solver is valuable for operator refactors, but cannot be a universal gate
  for correcting an algorithmic defect.

Suggested sequence:

1. Add independent final certificates and the failing warm-start/scale/
   offset/unloading tests; introduce honest termination statuses.
2. Center float geometry, correct overlap/activation logic, and make
   candidate verification global. Preserve existing successful benchmark
   accuracy, while deliberately rejecting the demonstrated false successes.
3. Integrate the compact near cache and accurate memory accounting.
4. Implement displacement reuse with periodic refresh and certification.
5. Benchmark staged q/precision, leaf sizes, and compressed/batched M2L
   against equal final certificates on fixed physical surfaces.
6. Evaluate a two-phase simplex/reduced-CG solver and sparse preconditioning;
   separately pursue the tangential projection-residual/Newton branch.

The acceptance criterion should be time and peak memory to a specified
physical/discrete accuracy, including build, coarse solves, verification and
fallback—not iteration count, contact area alone, or approximate-operator
residual alone.
